# 麦初心语｜蛋糕棒产品线升级项目
## 报价方案框架 v1（项目案）

### 一、当前确认口径
- 报价类型：项目案
- 起始阶段：从产品策略开始
- 价格处理：价格先不定，先把结构和边界讲清楚

### 二、项目案建议逻辑
这次不按单个包装设计散点报价。
而是按“产品策略 → 包装系统 → 首批设计执行”的项目案逻辑组织。

也就是说，这不是单个设计稿采购。
而是一轮围绕产品线升级的阶段性项目服务。

### 三、建议阶段结构

#### 阶段 1：产品策略梳理
目的：先把产品怎么打、打谁、怎么分层说明白。

建议内容：
1. 现有产品与样品资料整理
2. 当前问题与机会点诊断
3. 产品定位与表达方向梳理
4. 产品层级 / SKU角色建议
5. 渠道适配思路梳理
6. 婚庆礼赠渠道是否独立处理的建议

建议交付：
- 产品策略梳理文档
- 当前问题诊断结论
- 产品分层与方向建议

#### 阶段 2：包装系统规划
目的：把后续设计不是“零散出图”，而是有一套统一母系统。

建议内容：
1. 包装母系统方向定义
2. 品牌语气 / 命名风格建议
3. 口味、SKU、渠道的区分逻辑
4. 品质感提升路径建议
5. 对“胶囊感/零食感”的弱化策略

建议交付：
- 包装系统规划说明
- 包装表达原则
- 口味 / SKU / 渠道区分建议

#### 阶段 3：首批包装设计执行
目的：在前两阶段确认后，进入首批核心产品的正式设计。

建议内容：
1. 核心产品首批包装设计
2. 口味延展设计
3. 修改与定稿
4. 基础出图文件整理

建议交付：
- 首批包装设计稿
- 延展稿
- 定稿文件

#### 阶段 4：专项延展（可选）
这一段可不放进首轮主报价，作为追加项或选配项：
- 婚庆礼赠专项包装
- 展会物料/宣传物料
- 电商详情页
- 打样跟进与延展管理

### 四、当前建议的报价边界
本轮建议先按项目案报完整结构，但价格先后置。
也就是先确认：
- 服务阶段怎么分
- 每一阶段做什么
- 哪些属于主报价
- 哪些属于追加项

### 五、建议主报价范围
优先纳入主报价的内容：
1. 产品策略梳理
2. 包装系统规划
3. 首批包装设计执行

可后置或单列的内容：
1. 婚庆礼赠专项
2. 展会相关延展
3. 电商传播类设计
4. 超出首批范围的新增SKU
5. 打样陪跑与反复深改

### 六、当前不写死价格的好处
现在先不报死价格，是合理的。
因为还有几件事没完全锁死：
- 首批到底做几个产品
- 婚庆专项是否一起进主包
- 修改深度和轮次边界
- 是否含后续延展物料

所以现在最合适的动作不是马上填数字，
而是先把项目案结构搭准。

### 七、下一步正式报价前要补的内容
1. 首批纳入设计执行的产品范围
2. 婚庆礼赠专项是否进首轮主包
3. 每阶段的交付颗粒度
4. 修改轮次与确认节点
5. 价格口径

### 八、当前建议
我建议接下来正式报价就按下面这个总逻辑走：
- 用项目案方式报价
- 第一阶段从产品策略开始
- 再进包装系统规划
- 再进首批包装设计执行
- 价格最后补

这个逻辑更顺，也更像一个完整项目，不会显得只是接几个包装稿。
