# 麦初心语｜蛋糕棒产品线升级项目
## 报价方案框架 v0

### 一、当前报价目标
本轮不是直接开工，而是先把服务范围、交付项、阶段拆分和确认节点讲清楚。
确认后，再进入正式执行。

### 二、项目背景摘要
根据会议纪要与现场照片，目前项目核心不是单一包装改稿，而是围绕蛋糕棒相关产品做一轮“产品表达升级 + 包装系统整理 + 渠道适配准备”。

已知问题包括：
- 产品造型存在“胶囊感/零食棒感”，影响品质感联想
- 现有包装风格分散，产品系统没有完全收拢
- 口味、规格、渠道方向仍在收敛
- 婚庆礼赠渠道需要单独方案，不宜直接沿用现有零食逻辑

### 三、建议本轮报价按“前置方案整理”来报
建议先不把大量正式设计执行一次性全包进去。
先报“方案确认前置段”，确认后再进入设计执行段，更利于控制范围。

建议分成两个阶段看：

#### 阶段 A：报价确认前的方案整理段
目的：把做什么、做到哪里、怎么开工先说清楚。

可报价内容建议包括：
1. 项目资料梳理
   - 会议纪要整理
   - 现场样品与包装现状归纳
   - 当前问题点总结

2. 包装升级方向梳理
   - 当前包装问题诊断
   - 母系统风格建议
   - 不同产品/口味/渠道的区分逻辑建议

3. 报价方案与服务边界确认
   - 本轮服务范围
   - 不含项说明
   - 确认后开工节点说明

4. 执行阶段拆分建议
   - 哪些属于前置方案
   - 哪些属于正式设计执行
   - 哪些属于后续打样/延展/追加项

#### 阶段 B：确认后正式开工段
这一段先列入后续可执行范围，不一定现在一次性锁死价格。

可作为后续执行项候选：
1. 包装系统策略梳理
2. 单品包装视觉设计
3. 不同口味/SKU延展
4. 婚庆礼赠渠道专项包装方案
5. 提案稿修改与定稿输出
6. 打样跟进或物料延展（如需要）

### 四、建议报价结构
建议这次先给客户看的，不是“马上开干报价”，而是“先确认方案再执行”的结构。

建议报价结构可写成：

#### 方案一：先做前置梳理，再进执行
- 前置方案整理费
- 确认后执行费用另报 / 或按确认后的执行包启动

#### 方案二：前置梳理 + 第一阶段执行打包
- 前置梳理
- 第一批核心包装升级设计
- 后续延展另计

### 五、当前建议的服务边界
本轮建议先纳入：
- 项目现状整理
- 包装升级方向梳理
- 服务范围与交付边界确认
- 执行阶段报价结构建议

本轮建议暂不直接默认纳入：
- 全产品线全部包装同时重做
- 无限轮修改
- 打样落地执行管理
- 电商详情页/宣传物料/展会物料等额外设计
- 超出本次确认范围的新产品开发

### 六、建议确认节点
建议在正式开工前明确 3 个确认点：
1. 确认本轮先报“前置方案”还是“前置+首批执行”
2. 确认优先推进的产品对象
3. 确认报价通过后的开工方式、修改边界和交付节奏

### 七、下一步要补的内容
正式报价前，还需要补：
1. 本次准备按“散案 / 项目案 / 全案”中的哪一种去报
2. 每一阶段的具体交付项颗粒度
3. 是否拆成两个方案给对方选
4. 实际价格口径

### 八、当前建议
我建议优先采用：
- 先报“前置方案整理段”
- 确认后，再启动正式设计执行段

这样更稳。
因为现在产品方向、渠道侧重点、执行范围都还在收口中，直接一次性把所有执行打包，后续容易反复改范围。
