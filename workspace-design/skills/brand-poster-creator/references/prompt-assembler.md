# Prompt 精确装配器

用途：将蒸馏卡坐标数据、strategy 产出的文案策划、用户提供的参考图和风格要求，组装成**精确到坐标级别**的生图 prompt。

**重要**：生图 prompt 由 `scripts/assemble_prompt.py` 程序化生成，agent 不得手写 prompt。

蒸馏卡仅产出坐标和骨架图，不包含任何风格描述。风格完全由用户上传的参考图决定。

## 一、装配脚本

```bash
python3 scripts/assemble_prompt.py \
  --brief /path/to/brief.json \
  --distill /path/to/distill_card.json \
  --copywriting /path/to/copywriting.json \
  --style-profile /path/to/style_profile.json \
  --output /path/to/prompt_draft.md
```

脚本读取三/四个 JSON 数据源，输出结构化的 prompt 文件，并内置校验逻辑。`--style-profile` 为可选参数，有参考图风格提炼结果时传入。

## 二、输出结构

生成的 prompt 按以下顺序组织：

### 1. 画幅声明
```
这是一张竖版 9:16 比例的满版品牌海报。画面采用 100% 宽高画布。
```

### 2. 画面风格调性（有 style_profile 时）

在有风格提炼结果时，在画幅声明之后、参考图说明之前注入风格锚点区块，确保风格关键词在 prompt 最前面被生图模型读到：

```
== 画面风格调性 ==
整体气质：[overall_mood]
色彩关系：[color 逗号拼接]
画面质感：[material 逗号拼接]
避免风格：[avoid 逗号拼接]
```

无 style_profile 时此区块不出现。

### 3. 参考图说明

参考图排序（生图模型对排在前面的参考图赋予更高权重）：
1. **风格参考图**（第一位 — 决定画面气质）
2. **骨架图**（第二位 — 只约束构图结构）
3. **产品/IP 图**（第三位 — 画面主体外观保真）
4. **Logo**（最后一位 — 品牌标识原样使用）

每个参考图说明只保留一句话角色声明（≤30 字）：

**有 style_profile 时**（措辞更强，确保风格参考权重）：
```
参考图[0] 风格参考：完全根据该参考图的艺术风格调性进行参考。
参考图[1] 骨架图：严格按此构图和各区域比例布局。
参考图[2] 产品名：外观必须与此图一致，不得改变包装、颜色、图案。
参考图[3] 品牌 Logo：官方 Logo 文件，必须原样使用，不得自行绘制。
```

**无 style_profile 时**（保持原措辞）：
```
参考图[0] 风格参考：参考此图的色彩氛围和质感，不要照抄内容。
```

**注意**：
- 风格参考图有多张时，依次编号 [0]、[1]...，后面的骨架图和产品图编号顺延
- 如果没有风格参考图，骨架图从 [0] 开始编号

### 3. 视觉权力结构（有 hero_priority 时）

纯视觉指令，无工作流术语：
```
== 视觉权力结构 ==
- 画面绝对主角：[IP 名]，占据画面主导地位
- 陪衬元素：[陪衬描述]，不喧宾夺主，不占主位
- 禁止作为主视觉：[禁止元素]，不得在画面中作为突出元素出现
```

### 4. 画面布局（有蒸馏卡时）

遍历蒸馏卡的 `elements` 列表，逐个区域输出精确坐标描述：

```
== 画面布局（严格按以下坐标）==

【区域 el-X - 元素名】x:X% y:X% 宽:X% 高:X% z:X
[该区域的纯视觉描述]
```

各类型元素的描述规则：

| 类型 | 有 style_profile 时 | 无 style_profile 时（中性回退） |
|------|-------------------|--------------------------|
| background | 使用 `style_profile.background` 的描述 | 与风格参考图保持一致的背景。 |
| product_photo | 将参考图[N]（[名称]）放置在此区域中心，[名称]是画面第一视觉主体，以自然舒展的姿态展示。 | 同左 |
| title | 在此区域横排/竖排生成主标题文字：「[文案]」。字号大，使用[字体风格]的中文字体。 | 同左 |
| subtitle | 在此区域横排/竖排生成副标题文字：「[文案]」。字号小于主标题。 | 同左 |
| body_text | 在此区域生成文案：「[文案]」。文字[从左到右横排/从上到下竖排]。 | 同左 |
| decorative | 使用 `style_profile.decorative` 的描述 | 与整体风格协调的装饰元素，不喧宾夺主。 |
| logo | 使用参考图[N]的官方 Logo 文件，放置在此区域，不得自行生成或改写。 | 同左 |
| qr_code | 不需要生成二维码，此区域留白或放置轻量装饰。 | 同左 |
| 未知类型 | 以`style_profile.main_visual_style`呈现的[元素名]元素。 | [元素名]元素，按主题风格自然放置。 |

**关键原则**：默认描述不再带风格偏向（如"高级感"、"低饱和度"），避免"污染"画面风格。风格描述必须来自参考图提炼（style_profile），不能硬编码。

### 5. 负面约束

合并：蒸馏卡的 negative_constraints + 用户禁忌 + 通用硬约束。

通用硬约束始终追加：
- 满版效果，不要出现外边框或白色卡片感
- 产品外观必须保真（如果涉及产品图）
- Logo 必须使用官方原文件（如果涉及 Logo）

### 6. 无蒸馏卡时的降级处理

不使用坐标精确定位，使用相对位置描述，在 prompt 开头声明"无版式锁定"。

## 三、禁止混入 prompt 的工作流术语

以下词汇**不得**出现在给生图模型的 prompt 中：

| 禁止词 | 原因 |
|--------|------|
| 蒸馏卡、蒸馏、distill | 生图模型不理解的内部概念 |
| 主题语义、品类语义 | 抽象工作流术语 |
| 原海报 | 生图模型不知道什么是"原海报" |
| hero_1、hero_2、forbidden_hero | JSON 字段名，不是视觉描述 |
| brief.json、copy_planning | 内部文件名 |

正确做法：所有描述都是**纯视觉指令**，例如"画面绝对主角：品牌 IP 角色"而不是"hero_1：IP 角色"。

## 四、校验规则

脚本内置校验，生成 prompt 后自动检查：
- [ ] 不包含任何工作流术语
- [ ] 蒸馏卡的每个元素都有对应的区域描述
- [ ] 有文案的元素都已填入文案内容
- [ ] 参考图编号连续，与图片路径顺序对应
- [ ] prompt 长度在合理范围（200-5000 字符）

校验发现问题时以非零状态码退出，阻止错误 prompt 下发给生图模型。
