# 品牌海报版式蒸馏专家（v3.5）

## 何时使用
当用户要你做这些事时使用：
- 蒸馏一张海报，提取版式结构（骨架图 + 元素坐标）
- 给参考海报做版面分析：标题、产品图、Logo、价格区等元素的精确位置
- 按蒸馏 ID 调用版式数据，用于锁定画面版式
- 在蒸馏库网页中查看、编辑版式坐标
- 重新分析某张海报的版式
- 管理蒸馏库网页：查看、搜索、筛选、编辑、删除

## 版式蒸馏工作流
1. 用户提供参考海报图片
2. 创建新的蒸馏卡（v3.5 精简格式），包含 id / title / source_images
3. 运行 `layout_analyzer.py` 对海报进行 AI 版式分析，生成骨架图和元素坐标表
4. 用户可在网页端通过通过拖拽画布或编辑表格微调坐标
5. 保存后本地卡片即为最终版式锁定数据

## 数据存储方式
- **所有数据存储在本地 Mac 上**（`~/.openclaw/workspace/skills/brand-poster-distiller/`）
- 通过 frp 内网穿透实现远程访问
- 不需要上传到云端，不需要 rsync 同步
- 用户数据（users.json / sessions.json）也在本地

## 新蒸馏卡创建规则（强制遵守）

### ID 分配
- 先读取 `library-index.json`，找出当前最大编号（如 P-013）
- 新卡 ID = 最大编号 + 1（如 P-014）
- **禁止复用已删除的旧 ID**，即使旧卡文件已不存在
- 编号一旦分配过，永不回收复用

### 标题命名
- **必须从当前图片内容推导标题**，描述版式结构类型
- 标题只描述版式特征（如"顶部标题+中部场景插画+底部转化春节海报"）
- **禁止带入对话历史中的品类/主题语义**（如之前讨论过端午粽子，新卡标题也不能出现端午/粽子等词）
- 标题不包含具体品牌名、产品名、文案内容

### 标题命名示例
- ✅ "红底年节装饰型产品海报"（描述版式结构+色调）
- ✅ "顶部标题+中部场景插画+底部转化春节海报"（描述版式结构+节日）
- ❌ "粽子礼盒国风竖版海报"（带入品类语义，非版式描述）
- ❌ "小白心里软端午海报"（带入品牌名，版式不应绑定具体品牌）

## 新蒸馏卡创建步骤
1. 生成卡片 JSON（v3.5 精简格式），保存到 `cards/` 目录：
   - `id`：格式 `POSTER-DISTILL-P-XXX`
   - `title`：中文标题，描述版式类型（如"红底年节装饰型产品海报"）
   - `status`：初始为 `"pending_analysis"`
   - `distill_version`：`"v3.5"`
   - `source_images`：海报图片相对路径数组，**必须存放在 `data/source-images/` 目录下**，格式如 `data/source-images/POSTER-DISTILL-P-XXX.png`。禁止使用其他目录
   - `layout_analysis`：初始化为 pending 状态（空 elements/copy_planning_guide/negative_constraints）
2. 更新 `library-index.json`，将新卡片加入 cards 数组
3. 运行版式分析：`python3 scripts/layout_analyzer.py <DISTILL_ID>`
4. 刷新网页即可看到新卡片

## 版式卡片数据格式（v3.5）
每张卡片包含以下字段，**不生成 slug/subtitle/thumb/tags/summary 等冗余字段**：
- 基础信息：id, title, status, distill_version("v3.5")
- 图片来源：source_images（数组，相对路径，**统一存放在 `data/source-images/` 目录下**）
- 版式分析结果：layout_analysis（骨架图路径 + 元素坐标表 + 文案策划指南 + 负面约束）

元素坐标使用百分比定位（x, y, width, height 均为 0-100 的数值），支持响应式缩放。

## 风格和调性
版式蒸馏**不处理**风格和调性。风格和调性通过参考图上传 + 图生图的方式来借鉴。

## 下游注入机制（给生图工具）

版式蒸馏完成后，生图工具通过 `--distill-id` 参数调用指定版式。

### 两阶段工作流

**核心原则：先策划文案，再组装生图。** 不是把文案策划交给生图模型，而是由 AI agent 先完成文案策划，再填回骨架中。

```
用户意图 → AI agent 读取蒸馏卡空间指导 → AI agent 策划文案 → AI agent 组装完整 prompt → gpt-image-2 生图
```

### 蒸馏卡注入内容

蒸馏卡**只注入以下三项**，不做任何其他事情：

| 注入内容 | 形式 | 作用 |
|----------|------|------|
| 版式骨架图 | Image 参考 | 第一张参考图，标注"版式骨架，请严格按此构图" |
| 文案策划模板 | Prompt 文字 | 两阶段模板：Phase 1 列出需策划的文案区域，Phase 2 指导如何将文案填入 prompt |
| 负面约束列表 | Prompt 文字 | 自动生成的禁止项（基于版式特征推导） |

蒸馏卡**不注入**的内容：
- ~~summary~~（携带原海报主题语义，会污染新主题）
- ~~tags~~（携带原海报风格标签，会干扰用户指定的风格）
- ~~风格/色调/配色描述~~（这些由用户提供的参考图决定）
- ~~原海报文案~~（由 AI agent 根据主题自行策划）

### 文案策划模板（自动生成）

从 `layout_analysis.copy_planning_guide` 读取，格式如下：

```
## 第一阶段：文案策划（先完成以下编号，再进入第二阶段生图）

1. 【主标题区】横排 90%×22%（大） — 根据主题策划主标题（建议8-15字中文，或2-3行英文）
2. 【英文副标题】横排 56%×4% — 1行副标题（中文5-12字，或英文3-6个单词）
3. 【左侧竖排文案】竖排 5%×40% — 竖排中文文案（建议20-40字，分多行竖排）
4. 【右侧竖排文案】竖排 5%×40% — 竖排中文文案（建议20-40字，分多行竖排）
5. 【底部主题副标题】横排 60%×5% — 1行副标题（建议8-12字）
6. 【底部正文说明区】横排 84%×4% — 横排中文文案（建议20-50字）

## 第二阶段：生图 prompt 组装
将第一阶段策划好的文案填入对应区域，然后按以下结构组装最终 prompt 交给生图模型：
- 画面主角：放置在产品主图区（90%×60% 中心区域），根据用户主题自动生成或放置产品图
- 标题文案：放置在主标题区，使用策划好的文案，确保文字有实际含义，不要生成伪文字或乱码
- 参考图：骨架图只约束构图，风格参考图只约束气质，不互相照抄
- 标题文字必须有实际含义，不要生成伪文字、乱码或无意义的装饰性字符
```

**Phase 1** 只列出需要文案的区域（title、subtitle、body_text 等），每个区域标注：
- 区域名称（通用槽位名，不包含原海报文案）
- 排版方向（横排/竖排）
- 尺寸占比（推断文字容量）
- 文案策划要求（字数、语言建议）

**Phase 2** 指导 AI agent 如何将策划好的文案填回 prompt，确保：
- 文案有实际含义，不生成伪文字
- 文案与版式区域对应（标题放标题区，正文放正文区）

### 负面约束列表（自动生成）

从 `layout_analysis.negative_constraints` 读取，根据版式特征自动推导：

```
## 负面约束
- 不要破坏版式骨架的构图比例
- 标题文字必须有实际含义，不要生成伪文字、乱码或无意义的装饰性字符
- 不要在留白区域添加版式之外的额外元素
- 产品主图区必须占画面主导地位
- 竖排文案区必须保持竖排方向，不得改为横排
- 保持画面高留白、高级、呼吸感强，不要填满
```

### 完整注入示例

用户输入："调用 POSTER-DISTILL-P-012 的版式，基于这张风格图，生成春节海报"

AI agent 的操作流程：
1. 读取蒸馏卡的空间指导模板
2. 根据"春节海报"主题，为每个编号区域策划具体文案
3. 将策划好的文案填入完整 prompt
4. 挂载参考图（骨架图 + 风格图 + Logo + 产品图）
5. 调用生图脚本生成

最终拼给生图模型的输入：
- Image[0]：P-012 骨架图
- Image[1]：用户风格参考图
- Image[2]：用户 Logo
- Image[3]：用户产品图
- Prompt 包含：
  1. 用户原始意图（"生成春节海报"）
  2. 文案策划模板（两阶段，含具体策划好的文案）
  3. 参考图角色说明
  4. 负面约束列表

**蒸馏卡不提供**：风格描述、原海报文案、配色方案、主题标签（summary/tags）。这些完全由用户输入和参考图决定。

## 不要做
- 不要混入风格/色调/配色描述（这些通过参考图+图生图单独处理）
- 不要只输出聊天分析，不落卡、不入库
- 不要上传到云端或运行 rsync 同步（所有数据在本地）
- 不要使用 `publish_to_cloud.py` 或 `pull_from_cloud.py`（已废弃）
