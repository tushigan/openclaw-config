# 字段说明

本 skill 的项目文件在不破坏规范的前提下尽量中文化。

## 项目总表

`项目总表.yaml` 主要字段：

- `项目名称`：当前调研项目名称
- `项目编号`：项目唯一标识
- `项目目录`：本地项目绝对路径
- `运行模式`：当前项目默认是 `真实调研`
- `发起人`：包含 `姓名` 与 `飞书标识`
- `调研目标`：发起人希望回答的核心问题
- `调研范围`：本轮调研边界
- `受访对象来源方式`：`直接名单` 或 `范围建议`
- `受访对象范围说明`：对样本范围的自然语言说明
- `建议名单待确认`：范围建议模式下是否还没确认受访对象名单
- `是否可进入自动访谈`：是否允许开始自动推进访谈
- `是否可直接开始批量访谈`：是否可直接批量发起 1 对 1 邀约
- `项目开始时间`
- `项目截止时间`
- `当前阶段`：`立项 / 问题设计 / 受访对象确认 / 访谈进行中 / 分析总结 / 已关闭`
- `项目状态`：项目总体状态描述
- `执行架构`：包含 `发起代理 / 访谈代理 / 会话粒度 / 结果回收目标`
- `访谈执行设置`：默认发送账号、是否禁止用户身份发送、账号异常处理
- `访谈策略`：默认提问方式、默认交互形态、单人有效问题上限、收口信号
- `派发策略`：每批人数、批间隔分钟、首轮交互形态
- `派发批次记录`：分批外发计划
- `批次状态`：未生成 / 待就绪 / 待首发 / 已生成 / 无待首发对象
- `当前活跃受访对象数`：当前仍在等待或推进中的对象数
- `跟进策略`：催访节奏、截止提醒、最大跟进次数
- `截止时间变更记录`：所有 deadline 变更留痕
- `巡检设置`：cron 巡检配置与任务 ID
- `停止信息`：是否已停止、停止时间、停止原因、停止人
- `最终交付信息`：默认交付渠道、飞书文档标题、摘要消息状态、是否已发送最终报告、冻结版本号
- `样本概况`：总人数、已完成、已超时、已拒绝、待回复等
- `分析收口`：是否允许带缺口收口、样本缺口说明、最终收口时间

## 发送确认状态

- `已调用发送`：只说明 `message` 已返回成功，不能直接当成“确认发出”
- `已确认落到目标会话`：已用同一个 `chatId + messageId` 查到目标消息
- `已形成可回收 shared 会话`：真实 shared 会话已存在且绑定生效，可继续承接回收
- `已确认送达`：后续已经收到对方回复，可反证前序消息送达
- `发送记录存在但待人工确认`：在 research 会话日志里找到了发送记录，但还没有入站回复
- `发送记录存在但待人工确认`：在 `research` 会话日志里找到了发送记录，但还没有入站回复
- `发送记录缺失`：没在 research 会话日志里找到对应发送记录
- `核验口径冲突`：不同核验路径得出不同会话或不同结论，禁止继续写成功状态

补充说明：

- `recover-replies` 会优先扫描 `research-shared` 会话日志回补真实发送证据
- 如果 shared 会话里已经拿到 `messageId + chatId`，并且绑定已生效，可直接记为 `已形成可回收 shared 会话`
- 如果项目里只剩 `messageId` 没有 `chatId`，这属于半成品状态；补偿失败时会被清理回退，不能继续保留成 `待回复`

## 受访对象状态

- `待创建会话`：还没拿到真实 `执行会话ID`
- `待绑定`：会话已创建，但飞书私聊还没绑定过去
- `待首发`：真实会话和绑定都已就绪，但还没完成首发
- `待联系`：旧口径，规范化后会自动收敛到 `待创建会话`
- `已邀约`：已发首条访谈邀约
- `待回复`：已拿到 `messageId + chatId`，且还没收到有效回复
- `访谈中`：已开始对话式访谈
- `已完成`：访谈已完成并沉淀
- `已停滞待回`：对方明确说稍后回复，暂不继续追问
- `已停滞`：沟通中断，但还没到截止
- `已超时待收口`：已到截止，但最终飞书报告还没发出，晚到回复仍可补回
- `超时后补回`：截止后补回了有效信息，系统需刷新分析与交付草案
- `已关闭后回复`：最终飞书报告已发出后才回复，只记录不改主报告
- `已超时`：到截止后仍未完成
- `已拒绝`：对象明确拒绝参与

## 会话绑定状态

- `未绑定`：还没有把受访对象飞书私聊绑定到专属 shared 会话
- `已绑定`：后续回复会持续进入对应的 `research-shared` 会话
- `已解绑`：项目停止或收口后，旧绑定已清理

## 链路验收方案输出

`acceptance-plan` 会返回一份链路验收执行清单，重点字段包括：

- `允许执行`
- `阻止原因`
- `执行限制`
- `前置检查`
- `会话创建`
- `会话绑定`
- `首轮触达`
- `回收验证`
- `第二轮触达`
- `清理`

这份清单只用于验证：

- 能否创建专属 `research-shared` 会话
- 能否把飞书私聊绑定过去
- 能否从 shared 会话发首条卡片
- 对方回复后，是否回到同一条 shared 会话并继续

## 发送核验口径

- 首发验收优先看 `message` 返回里的 `messageId + chatId`
- shared 子会话里的 `message` 工具成功回执，是发送核验的主证据
- `open_id` 路径的消息读取，不作为默认的发送验收依据
- 没有真实 `执行会话ID`、没有 `messageId + chatId` 时，不允许把对象写成 `待回复`
- 不允许用临时脚本直接改 YAML 充当主流程成功证据

## 访谈策略默认值

- `默认提问方式`：`判断题优先`
- `默认交互形态`：`文本选择题`
- `开放问答最晚触发条件`：判断题和选择题仍不足以拿到关键信息时，且一次只问 1 个问题
- `首轮结构`：`说明消息+1个短文本选择题`
- `单人有效问题上限`：`4`
- `收口信号`：
  - `是否使用过`
  - `主要使用场景或主要阻力`
  - `培训期待或改进方向`

## 飞书交付文件

项目收口后会额外生成：

- `输出/飞书文档正文.md`
  - 供 `feishu_create_doc` 直接创建文档
- `输出/飞书摘要消息.txt`
  - 发给发起人的摘要消息
- `输出/飞书交付清单.json`
  - 真实交付动作清单
  - 包含首选顺序与 fallback 顺序
  - 交付成功后还要运行 `delivery-complete`，把项目冻结

## 飞书交付清单说明

`飞书交付清单.json` 里重点看：

- `preferred_delivery`
  - 默认是 `feishu_doc_then_message`
- `fallback_delivery`
  - 默认是 `message_file_then_text`
- `target`
  - 飞书发送目标
- `deliverables`
  - 文档正文、摘要消息、报告附件路径
- `agent_delivery_contract`
  - 真实交付动作要求
  - 只有工具调用成功后，才算交付完成
