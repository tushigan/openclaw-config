# 然利品牌档案缺失问题 - 根因分析报告

## 📋 问题概述

**现象**：用户在 2026-06-15 推进"然利品牌升级视频"任务时，系统没有记录然利的品牌档案。

**发现时间**：2026-06-15 晚

**影响**：后续任务无法从项目记忆系统获取然利的品牌定位、调性、视觉规范等信息，导致每次都需要重新查找历史对话。

---

## 🔍 根因分析

### 问题 1：自动增长机制没有触发 ❌

#### 应该发生的流程
1. ✅ Agent 查询品牌档案 → 返回"不存在"
2. ❌ **暂停任务，提示用户：是否创建品牌档案？**
3. ❌ 用户确认后，从对话中提取品牌信息并创建档案
4. ❌ 继续执行任务

#### 实际发生的流程
1. ✅ Agent 查询品牌档案 → 返回"不存在"
2. ❌ **Agent 直接跳过建档，用对话 brief 继续做**
   - Agent 判断："品牌档案查询为空，所以这次先按对话 brief + 本地可用 Logo/门店/物料图来做，避免空等"
3. ✅ 生成了 4 张故事板产物
4. ❌ **没有回写品牌信息到记忆系统**

#### 为什么机制没有触发？

**原因 1：AGENTS.md 规则没有被严格执行**
- 规则要求：品牌不存在时应暂停任务，提示建档
- 实际行为：Agent 选择"避免空等"，直接跳过建档
- Agent 优先级判断：**"尽快做出产物" > "先建立档案"**

**原因 2：缺少强制检查点**
- 当前机制依赖 Agent 自觉执行
- 没有硬性校验："品牌不存在时必须先建档，否则不允许继续"
- Agent 有自主决策权，可以绕过规则

**原因 3：Agent 没有意识到后果**
- Agent 认为"本次任务可以用对话 brief 完成"
- 没有意识到"品牌档案缺失会导致后续所有任务都无法获取品牌信息"
- 缺少"长期影响"的判断逻辑

---

### 问题 2：两套记忆系统架构不兼容 ❌

#### Boss skill 的 `agency_project` 系统
```
projects/
└── 品牌名/                    # 品牌作为顶层目录
    ├── _brand-profile.json
    └── _brand-assets/
```

#### 顶层记忆系统 `scripts/memory/`
```
projects/
└── 客户名/                    # 客户作为顶层目录
    └── 品牌名/
        ├── _brand-profile.json
        └── _brand-assets/
```

#### 导致的问题
- `agency_project.create_or_get_brand()` 创建了 `/projects/然利/`（品牌作为顶层）
- 查询脚本 `scripts/memory/query.py` 期望 `/projects/客户名/然利/`（客户→品牌两层）
- **结果**：品牌档案创建成功，但查询失败 ❌

#### 为什么会有两套系统？

1. **Boss skill** 是从 `workspace-business` 迁移过来的旧系统，采用"品牌为顶层"的扁平结构
2. **顶层记忆系统** 是后来优化的新系统，采用"客户→品牌"的层级结构
3. 两套系统没有完全统一，导致兼容性问题

## 🔧 需要修复的根本问题

### 问题 1：统一两套记忆系统架构 ⚠️ 高优先级

**当前状态**：
- Boss skill 的 `agency_project` 使用"品牌顶层"结构
- 顶层记忆系统使用"客户→品牌"结构
- 两套系统不兼容，手动创建需要手动修复目录

**建议方案**：

**选项 A：废弃 Boss skill 的 `agency_project`，统一使用顶层记忆系统**
- ✅ 彻底解决兼容性问题
- ✅ 只维护一套系统
- ❌ 需要修改 Boss skill 的所有调用

**选项 B：修改 `agency_project` 适配"客户→品牌"结构**
- ✅ 保留现有调用方式
- ✅ 新创建的档案自动兼容
- ⚠️ 需要修改 `create_or_get_brand()` 函数，增加 `client_name` 参数

**选项 C：增加兼容层，自动检测并修复目录结构**
- ✅ 无需修改现有代码
- ✅ 自动兼容两种结构
- ❌ 增加复杂度

**推荐方案**：**选项 B** - 修改 `agency_project` 适配新结构

---

### 问题 2：强化自动增长机制的执行 ⚠️ 高优先级

**当前状态**：
- 规则写在 AGENTS.md 中，但 Agent 可以自主选择是否执行
- 缺少强制检查点

**建议方案**：

**方案 A：增加强制检查点（工具层拦截）**
- 在 `exec` 工具执行前，检查是否有品牌档案
- 如果品牌不存在，**拒绝执行任务**，强制要求先建档
- ✅ 100% 执行率
- ❌ 可能过于严格，影响灵活性

**方案 B：增强 AGENTS.md 规则优先级提示**
- 在规则中明确标注："**这是强制规则，不得跳过**"
- 增加后果说明："跳过建档会导致后续所有任务无法获取品牌信息"
- ✅ 保持灵活性
- ⚠️ 依赖 Agent 理解和执行

**方案 C：任务完成后自动回写品牌信息**
- Agent 跳过建档时，任务完成后自动提取品牌信息并创建档案
- ✅ 即使 Agent 跳过，也能保证信息被记录
- ⚠️ 需要增加"任务后置钩子"机制

**推荐方案**：**方案 B + 方案 C 组合**
- 先强化规则提示，提高 Agent 主动建档率
- 同时增加任务后置钩子，兜底保证信息被记录

---

### 问题 3：品牌资产归档机制缺失 ⚠️ 中优先级

**当前状态**：
- 任务中使用的品牌资产（Logo、门店图、包装图）散落在 `workspace-design/images/` 等临时目录
- 没有自动归档到 `projects/客户名/品牌名/_brand-assets/`

**建议方案**：

**任务完成后，自动归档品牌资产**：
- 检测任务中使用的品牌相关图片（Logo、门店、包装、VI 手册）
- 自动复制到 `_brand-assets/logos/`、`_brand-assets/reference-images/` 等目录
- 在品牌档案中记录资产路径
