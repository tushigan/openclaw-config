# dreamina-reference-video Skill 优化日志

## 2026-05-28：IP 约束传递优化

### 问题背景

在实际使用中发现，即使在 `identity_forbidden` 中明确指定了约束（如"禁止长出额外翅膀"），最终生成的视频仍然会出现违反约束的情况。

经过分析发现，问题的根源不在于约束传递链路（约束确实被传递到了所有提示词中），而在于：

1. **AI 模型的约束遵守能力有限**：参考图的视觉权重远大于文字约束权重
2. **负向约束理解困难**："不要 X" 这类负向指令对 AI 模型效果较差
3. **故事板表达模糊**：黑白线稿对复杂结构的表达不足，容易被模型误解

### 优化方案

实施了三个通用优化方案：

#### 方案 1：约束多点注入

**目标**：将关键约束提升到提示词开头，增加权重。

**实现**：
- 新增 `build_constraint_header()` 函数
- 在身份板、故事板、视频提示词的开头注入约束头部
- 约束头部包含：正确理解、严格禁止、对比说明、结构真相

**效果**：
- 约束在提示词中的位置从末尾提升到开头
- 模型在生成时首先看到约束，而不是最后才看到

#### 方案 2：约束表达优化引擎

**目标**：将负向约束改写为更有效的表达方式。

**实现**：
- 新增 `enhance_constraint_expression()` 函数
- 自动识别常见约束类型（翅膀、手、尾巴等）
- 将负向约束改写为：
  - **正向替代描述**：告诉模型应该是什么样
  - **强化负向**：使用"严禁"、"绝对不能"等更强的否定词
  - **对比说明**：明确"不是 X，而是 Y"

**示例**：

原始约束：
```
禁止长出额外翅膀
```

优化后：
```
正确理解：
- 身体两侧是主体造型的侧面轮廓，不是独立肢体

严格禁止：
- 严禁添加任何翅膀、翼状结构或类似飞行器官

对比说明：
- 不是：普通动物 + 翅膀；而是：特定造型的完整体块
```

**效果**：
- 负向约束转化为正向描述 + 强化负向
- 模型更容易理解"应该是什么样"，而不只是"不要什么"

#### 方案 3：增强人工检查清单

**目标**：根据约束自动生成针对性检查项，提供更具体的验证指导。

**实现**：
- 新增 `generate_constraint_checklist()` 函数
- 根据约束类型自动生成具体检查项
- 针对翅膀约束生成 3 个检查点（身份板、故事板、侧面视角）
- 针对手/手臂约束生成 2 个检查点
- 增加醒目的警告提示

**示例**：

原始检查清单：
```
- [ ] 是否出现了以下禁止变形？
  - [ ] 禁止长出额外翅膀
```

优化后：
```
### 2. IP 约束检查（最重要）

**⚠️ 关键**：如果参考图违反了约束，后续视频必然违反约束！

**禁止变形检查**（以下特征应该全部没有出现）：
- [ ] ❌ 身份板中角色两侧是否出现了翅膀状结构？（约束：禁止长出额外翅膀）
- [ ] ❌ 故事板每一格中角色是否保持了无翅膀状态？
- [ ] ❌ 侧面视角时是否错误地出现了翅膀轮廓？

**如果发现违反约束，必须重新生成对应参考图！**
```

**效果**：
- 检查清单更具体、更易操作
- 用户更容易发现参考图中的约束违反
- 减少"参考图有问题但没发现"的情况

### 通用性设计

所有优化方案都是**项目无关**的：

1. **自动识别约束类型**：通过关键词匹配（翅膀/wing、手/hand、尾巴/tail）
2. **可扩展**：添加新的约束类型识别规则很容易
3. **向后兼容**：不影响没有复杂约束的简单项目
4. **通用处理**：未识别的约束也有通用强化处理

### 代码变更

**新增函数**：
- `enhance_constraint_expression()` - 约束表达优化
- `build_constraint_header()` - 约束头部生成
- `generate_constraint_checklist()` - 检查清单生成

**修改函数**：
- `build_prompts()` - 在提示词开头注入约束头部
- `write_summary()` - 使用新的检查清单生成逻辑

**文件**：
- `scripts/workflow.py` - 主要优化逻辑

### 测试验证

创建了 `test_constraint_optimization.py` 测试脚本，验证：
- 约束表达优化功能
- 约束头部生成功能
- 检查清单生成功能

所有测试通过 ✅

### 预期效果

1. **提高约束遵守率**：通过多点注入和表达优化，提高 AI 模型对约束的重视程度
2. **减少人工返工**：通过增强检查清单，更容易在参考图阶段发现问题
3. **通用适用**：适用于所有有复杂 IP 约束的项目

### 后续优化方向

1. **故事板渲染模式优化**（中期）：根据约束复杂度自动选择彩色简化版 vs 黑白线稿
2. **自动验证钩子**（长期）：接入视觉模型（GPT-4V）自动检查参考图是否违反约束

## 2026-05-28 补充优化：明确故事板文字标注要求

### 问题背景

在实际使用中发现，当第一轮生成的故事板不符合要求（如横向长条、角色违反约束）时，agent 重新生成故事板会出现问题：

**第一轮生成**（使用 skill 标准流程）：
- ✅ 有文字标注（景别、运镜、动作描述）
- ✅ 有箭头指示运镜方向
- ✅ 专业导演分镜板风格

**第二轮重新生成**（agent 临时写提示词）：
- ❌ 没有文字标注
- ❌ 没有箭头指示
- ❌ 丢失了专业分镜板的标准要素

### 根本原因

Agent 在重新生成时：
1. **绕过了 skill 的标准流程**，直接调用 gpt-image-2-gen
2. **使用临时简化提示词**，重点放在修正画幅和约束
3. **丢失了标准故事板提示词的结构化要求**

原标准提示词虽然有"每格都给明确镜头语言"，但没有**明确要求文字标注和箭头**，导致：
- 第一轮：AI 根据"黑白导演分镜稿"自然生成了文字标注
- 第二轮：临时提示词缺少这个隐含要求，AI 就不生成了

### 优化方案

在标准故事板提示词中**明确要求文字标注和箭头**：

**新增要求 3**：
```
3. **每格必须包含文字标注**：用文字标注景别（特写/中景/全景）、运镜方向（推/拉/摇/跟）、关键动作描述。这是专业导演分镜板的标准要求。
```

**新增要求 4**：
```
4. **使用箭头指示运镜方向和动作路径**：让分镜板的镜头语言和动作意图一目了然，提高可读性和执行性。
```

### 效果

1. **标准化输出**：无论第几轮生成，只要使用标准流程，都会有文字标注和箭头
2. **提高可读性**：分镜板的镜头语言和动作意图更清晰
3. **减少歧义**：明确的文字标注减少视频生成时的理解偏差

### 代码变更

**修改函数**：
- `build_prompts()` - 故事板提示词增加文字标注和箭头要求

**文件**：
- `scripts/workflow.py` - 第 850-851 行（新增要求 3 和 4）

### 最佳实践建议

**当参考图不符合要求时**：
1. ❌ **不要**直接调用 gpt-image-2-gen 重新生成
2. ✅ **应该**修改 brief.json 中的相关字段
3. ✅ **应该**重新运行 `generate-refs` 步骤使用标准流程

这样可以确保：
- 使用标准提示词模板
- 保留所有结构化要求
- 约束传递完整

## 2026-05-29：视频提交流程优化

### 问题背景

用户在实际使用中反馈两个问题：

**问题 1：无法选择视频生成通道**
- 当前直接使用 brief.json 中的 `quality_tier` 提交
- 不同通道消耗的积分差异很大（draft ~50-100 积分，final ~150-300 积分）
- 用户无法在提交前理性选择通道

**问题 2：提交后无反馈**
- 提交视频生成后 agent 没有反应
- 需要用户主动询问"检查一下进度"才会查询
- 用户体验差，不知道任务是否在进行中

### 优化方案

#### 优化 1：增加通道选择确认环节

**新增功能**：
- `get_quality_tier_options()` - 获取所有通道选项及详细信息
- `estimate_credit_cost()` - 估算积分消耗
- `format_quality_tier_info()` - 格式化通道信息供显示

**通道对比**：

| 通道 | 模型 | 分辨率 | 速度 | 积分（估算） | 适用场景 |
|------|------|--------|------|-------------|---------|
| draft | seedance2.0fast | 720p | 5-8分钟 | ~50-100 | 快速验证、打样测试 |
| final | seedance2.0_vip | 1080p | 15-20分钟 | ~150-300 | 正式交付、客户展示 |

**工作流程**：
1. 在 submit-video 前，agent 调用 `format_quality_tier_info()` 显示通道信息
2. 使用 AskUserQuestion 让用户选择通道
3. 根据用户选择更新 brief.json 中的 `quality_tier`
4. 提交视频生成

**SKILL.md 更新**：
- 在步骤 7 增加"确认视频生成通道"说明
- 提供 AskUserQuestion 使用示例
- 说明每个通道的特点和适用场景

#### 优化 2：自动轮询机制

**问题分析**：
- 原代码已有 `--poll=15`，但只轮询 15 秒，远不够
- draft 通道需要 5-8 分钟，final 通道需要 15-20 分钟

**优化方案**：
- 新增 `get_poll_timeout()` 函数，根据质量档动态设置轮询时间
- draft 通道：轮询 10 分钟（600 秒）
- final 通道：轮询 20 分钟（1200 秒）
- 默认：15 分钟（900 秒）

**代码变更**：
```python
def get_poll_timeout(quality_tier: str) -> int:
    timeout_map = {
        "draft": 600,   # 10 分钟
        "final": 1200,  # 20 分钟
    }
    return timeout_map.get(quality_tier, 900)

# 在 build_dreamina_command() 中使用
poll_timeout = get_poll_timeout(brief["quality_tier"])
cmd.extend([f"--poll={poll_timeout}"])
```

**效果**：
- 提交后自动轮询任务状态，无需用户手动查询
- 生成完成后自动下载结果
- 轮询超时时间根据通道自动调整

**SKILL.md 更新**：
- 在步骤 8 说明自动轮询行为
- 建议 agent 在提交后告知用户预估时间
- 说明系统会自动轮询，无需手动查询

### 用户体验改进

**优化前**：
1. 直接提交，用户不知道消耗多少积分
2. 提交后无反馈，需要手动询问进度
3. 轮询时间太短（15秒），实际需要 5-20 分钟

**优化后**：
1. 提交前显示通道对比，用户理性选择
2. 提交后自动轮询，定期检查状态
3. 轮询时间根据通道自动调整，覆盖实际生成时间
4. 生成完成后自动下载，无需手动操作

### 代码变更

**新增函数**：
- `get_poll_timeout()` - 根据质量档返回轮询超时时间
- `get_quality_tier_options()` - 获取所有通道选项
- `estimate_credit_cost()` - 估算积分消耗
- `format_quality_tier_info()` - 格式化通道信息

**修改函数**：
- `build_dreamina_command()` - 使用动态轮询超时时间

**文件**：
- `scripts/workflow.py` - 主要优化逻辑
- `SKILL.md` - 更新步骤 7 和步骤 8
- `FEATURE_DESIGN_VIDEO_SUBMISSION.md` - 详细设计文档

### 注意事项

1. **积分消耗是估算值**：实际消耗可能因视频复杂度、时长等因素有所不同

2. **轮询超时处理**：
   - 如果轮询超时，任务可能仍在进行中
   - 用户可以稍后手动查询：`dreamina query_result --submit_id=xxx`

3. **通道选择建议**：
   - 打样阶段：使用 draft 通道，快速验证
   - 正式交付：使用 final 通道，最高质量
   - 不确定时：先用 draft 验证，满意后再用 final 生成正式版

4. **Agent 行为指导**：
   - 必须在提交前让用户选择通道，不要擅自决定
   - 提交后告知用户预估时间和轮询状态
   - 轮询期间如果用户发消息，应该响应并说明"视频生成中"
