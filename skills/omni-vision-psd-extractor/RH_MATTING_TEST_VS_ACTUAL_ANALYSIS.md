## 🔍 可能原因分析

### 1️⃣ HB 余额不足（最可能 ⭐⭐⭐⭐⭐）

**现象**:
- 第一次测试：HB 充足 → 成功
- 第二次调用：HB 不足 → 404

**为什么返回 404 而不是余额不足错误？**
- 某些 API 实现会将"无权访问"统一返回为 404
- RunningHub 可能认为"余额不足 = 无权使用该服务"

**验证方法**:
1. 登录 [runninghub.cn](https://www.runninghub.cn)
2. 查看"我的账户" → "HB 余额"
3. 查看"消费记录"，找到 TaskId: 2066734755180924930
4. 确认该任务是否扣费

**解决方法**:
- 充值 HB 算力币
- 或继续使用本地去绿幕（当前降级方案）

---

### 2️⃣ API 限流（可能 ⭐⭐⭐）

**现象**:
- 短时间内连续调用（测试 + 实际运行）
- 触发 RunningHub 的限流保护

**为什么返回 404？**
- 某些限流实现会返回 404 而不是 429
- 目的是防止恶意探测 API 结构

**验证方法**:
- 等待 5-10 分钟后重试
- 如果成功，说明是限流问题

**解决方法**:
- 降低调用频率
- 添加重试机制（带延迟）

---

### 3️⃣ WebappId 临时失效（可能 ⭐⭐）

**现象**:
- WebappId: 2064637853572878337 可能是临时应用
- 测试后被禁用或权限变更

**验证方法**:
1. 登录 RunningHub
2. 访问应用详情页：
   ```
   https://www.runninghub.cn/ai-detail/2064637853572878337
   ```
3. 检查应用状态（是否公开、是否可用）

**解决方法**:
- 如果应用被禁用，需要找到新的可用抠图应用
- 或使用本地去绿幕（当前降级方案）

---

### 4️⃣ Cloudinary URL 失效（可能 ⭐）

**现象**:
- RH API 要求图片 URL 可访问
- Cloudinary URL 可能有时效性

**为什么第一次成功？**
- URL 刚生成时有效
- 几分钟后过期或被限流

**验证方法**:
- 检查两次调用的 Cloudinary URL 是否相同
- 尝试在浏览器中打开第二次的 URL

**解决方法**:
- 每次调用时重新上传到 Cloudinary
- 或使用持久化的图床

---

### 5️⃣ API Token 过期（可能性低 ⭐）

**现象**:
- API Key 有时效性
- 第一次成功时有效，第二次已过期

**为什么可能性低？**
- 通常 Token 过期返回 401，不是 404
- API Key 通常是长期有效的
