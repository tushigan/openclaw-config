# 食品详情页输入清单

在进入详情页策略前，至少先确认以下输入。

## 1. 载体与投放
- 主要平台是什么
- 手机端 / PC 端 / 双端
- 当前优先服务哪一端

## 2. 当前要产出的阶段物
必须先说清：
- 高精度黑白手稿
- 最终设计稿
- 拼接长图

不要一边聊一边变。

## 3. 产品结构事实（必须前置）
先锁死这些事实：
- 空心 / 夹心
- 单层 / 多层
- 是否流心
- 是否涂层
- 是否带馅
- 是否需要展示断面

### 使用脚本锁定（推荐）
运行 `scripts/lock_product_facts.py` 将上述事实锁定为结构化 JSON，输出格式如下：

```json
{
  "brand": "品牌名",
  "product": "产品名",
  "category": "类目",
  "structure": {
    "type": "clamped",
    "description": "夹心（上下层+中间夹酱）",
    "layers": 3,
    "is_coated": false,
    "is_molten": false,
    "cross_section_needed": true
  },
  "flavors": ["口味1", "口味2"],
  "main_flavor": "主推口味",
  "flavors_separate": false,
  "emboss": {"type": "bear_face", "description": "熊脸压纹"},
  "packaging_required": true,
  "logo_locked": true,
  "avoid": ["英文", "占位框", "注释线"],
  "style_note": ""
}
```

该 JSON 必须注入到后续所有图像生成的 prompt 中，作为 `{{PRODUCT_FACTS_INJECTION}}` 的内容来源。

如果这些没锁，后面整页方向很容易错。

## 4. 口味与产品露出要求
- 一共有几个口味
- 哪些口味必须单独露出
- 哪些口味可以合并展示
- 是否需要总览屏
- 是否有主推口味

## 5. 包装与品牌资产要求
- 哪些包装必须露出
- 包装是可参考生成，还是必须硬锁
- logo 是否必须真实使用
- 是否已有品牌视觉规范

## 6. 图片资产分类
把输入图分成三类：

### A. 硬资产
不能乱变：
- 包装图
- logo
- 指定产品图
- 指定品牌 icon

### B. 结构参考
用于手稿或版式参考：
- 线稿
- 黑白手稿参考
- 详情页结构参考

### C. 风格参考
用于控制调性，不用于硬锁结构：
- 氛围图
- 版式风格图
- 光影质感图

## 7. 页面任务与目标
- 这次详情页主要想解决什么
- 更偏新品种草 / 电商转化 / 品牌感建立 / 招商说明
- 最终最想让用户记住什么

## 8. 生成前最后确认
在正式生成手稿前，再确认一次：
- 连续段是不是至少 2 屏一张
- 黑白手稿精度要求是不是已对齐
- 逐屏文案是不是已经能直接喂给手稿层

如果这 3 条没确认，不建议直接开生成。
