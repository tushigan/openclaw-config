# 服务清单参考

## 主清单与机器读取版

1. 人工维护主清单固定放在 `assets/standards/service-catalog.xlsx`。
2. 机器读取版固定放在 `data/service-catalog.json`。
3. 如果主清单更新，先重建 data/service-catalog.json。
4. 更具体地说，如果主清单更新时间晚于 JSON，或者 JSON 结构不对，就先重建，不要继续沿用旧 JSON。

## 正式报价时怎么使用

1. 正式报价必须优先读取 `data/service-catalog.json`。
2. 正式结构先从标准服务项里选，再组合成 `阶段 / 项目 / 任务`。
3. `service_catalog_refs` 尽量同时记录在项目层和任务层，方便后续追溯。
4. 如果某个任务暂时找不到对应标准条目，不要立刻中断报价，而是按待入库规则处理。

## 任务细拆时怎么用

1. 不要只拿最少的 2-3 个标准任务去过结构。
2. 应先按客户真实需求筛选范围，再在该范围内尽量把可独立成价值动作的标准任务拆出来。
3. `包装策划 / 包装设计 / 包装落地 / 婚庆专项 / 详情页策划 / 详情页设计 / 主图策划设计 / 渠道策略` 这些高可拆板块，默认先横向检查同类条目是否还能细拆。
4. 如果当前项目最终确实只能对应 2-3 个任务，可以保持克制；但必须确认其它标准条目确实不适用，不能因为省事少写。
5. 对用户能明显感知价值的动作，优先拆成独立任务。比如：策略判断、结构定义、创意提案、设计执行、打样、印前、跟印、主图、摄影脚本、修图跟拍等。

## 最新工作簿读取口径

当前主清单默认读取 `汇总表`，重点字段是：

1. `选择`
2. `模块`
3. `模块`
4. `项目`
5. `任务`
6. `说明`
7. `服务部门`
8. `计划时间(工作日)`
9. `交付成果`
10. `建议报价`

表尾如果还有空列，要自动忽略。

## 新条目的待入库规则

1. 本次报价里出现的新条目，先完成正式报价，再进入公司总待入库池。
2. 公司总待入库池文件是 `data/catalog-pending-review.json`。
3. 待入库池里的记录，至少要能说明客户、项目、版本、建议放入的位置、任务名、说明和原因。
4. 用户确认入库后，要先更新主清单，再重建 `data/service-catalog.json`，然后删掉对应待入库记录。
5. 本次不入库则移出总池，但保留项目级记录，说明“本次出现过该新条目，但用户暂不入库”。
