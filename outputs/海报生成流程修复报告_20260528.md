## 问题总结

### 问题 1：首轮跳过文案确认直接生图

**现象**：
- 林媛媛提供完整的品牌海报需求（品牌 logo、产品图、包装图、文案要求）
- main agent 读取 `image-task-router` 后，直接调用 `gpt-image2-gen` 手写 prompt 生图
- 完全跳过 `brand-poster-creator` skill 的 9 个标准步骤
- 没有在文案策划阶段等待用户确认

**根因**：
- `image-task-router` 作为"总闸门"优先级高于 `brand-poster-creator`
- 品牌海报需求被错误归类为 `simple_model_generation`（简单生图）
- 导致绕过了需求收集、文案策划、创意确认等关键步骤

### 问题 2：后续修改使用本地 PIL 拼图

**现象**：
- 用户提出修改要求后，main agent 派发 design-shared agent 处理
- design-shared agent 使用 `PIL`、`Image.paste()` 等方法进行本地图像拼接
- 产出的图片有明显拼贴感、边缘不自然、光影不一致

**根因**：
- design-shared agent 在正式生图失败或超时后，自行降级到本地拼图
- 违反了 `image-task-router` 和 `brand-poster-creator` 明确禁止的"本地最终合成"规则
- workspace-design/AGENTS.md 的禁止规则不够强硬，没有阻止这种行为

---

## 修复方案

### 修复 1：禁用 image-task-router skill ✅

**理由**：
- 专业 skill（brand-poster-creator）已有完整的触发词和流程设计
- image-task-router 作为"总闸门"反而干扰了正确的 skill 调用
- 防止 PIL 拼图应该在 AGENTS.md 中约束，而不是通过路由 skill

**操作**：
```bash
mv /Users/a123/.openclaw/workspace/skills/image-task-router \
   /Users/a123/.openclaw/skills-store-disabled/image-task-router-disabled-20260528
```

### 修复 2：强化 brand-poster-creator 的触发优先级 ✅

**位置**：`workspace/AGENTS.md`

**新增规则 0.1.1**：
```markdown
### 0.1.1 品牌海报任务强制路由
当用户需求包含以下任意关键词时，**必须**优先调用 `brand-poster-creator` skill：
- 品牌海报 / 海报生成 / 做张海报 / 做个海报
- 节日海报 / 春节海报 / 中秋海报 / 中考海报 / 端午海报 / 国庆海报
- 产品海报 / 产品 KV / 营销海报 / 推广海报
- 或用户提供了品牌 logo、产品图、包装图等品牌素材

`brand-poster-creator` 包含完整的需求收集、文案策划、创意确认、生图、交付流程，不得跳过任何确认步骤。
```

### 修复 3：强化禁止 PIL 拼图规则 ✅

**位置**：`workspace/AGENTS.md` 和 `workspace-design/AGENTS.md`

**新增规则 1.1.1**：
```markdown
### 1.1.1 禁止本地拼图作为正式交付（硬约束）

**绝对禁止**以下做法作为正式图片交付：
- 使用 PIL / Pillow / OpenCV / ImageMagick 进行最终图像合成
- 使用 `Image.paste()`、`alpha_composite()`、`Image.blend()` 等方法拼接正式海报/产品图
- canvas 手工合成
- 局部硬贴
- 先本地拼图，再冒充正式改图结果

**允许的本地图像操作**（仅限辅助用途）：
- 遮罩检测（mask detection）
- `mask_spec.json` 规划
- 预览图生成（preview generation）
- 图像压缩（compression）
- 投递准备（delivery preparation）

**正式生图失败时的正确处理**：
1. 记录失败原因到 `generation_result.json` 或等价结果文件
2. 返回失败状态给 `main` agent
3. 由 `main` agent 决定是否重试、切换 provider 或告知用户
4. **不得**自行产出本地合成图顶替正式结果

**违反此规则的后果**：
- 本地拼图产出的图片会有明显拼贴感、不自然的边缘、光影不一致
- 用户会明确感知到"这是拼出来的"，而不是"AI 生成的"
- 必须重新走正式生图链路
```

### 修复 4：增加 brand-poster-creator 的强制确认机制 ✅

**位置**：`skills/brand-poster-creator/SKILL.md`

**Step 5 和 Step 5.8 新增硬门禁**：
```markdown
### 强制确认机制（硬门禁）

**未得到用户明确确认前，禁止进入下一步。**

确认方式：
- 用户回复「确认文案」/「确认创意」或「OK」或「可以」或「没问题」
- 或用户提出具体修改要求后再次确认

**禁止行为**：
- 自动假设用户已确认
- 沉默视为同意
- 直接进入下一步
- 在用户未回复时继续执行后续步骤
```

## 总结

本次修复通过以下措施解决了海报生成流程的两个核心问题：

1. **禁用干扰性的路由 skill**：移除 image-task-router，让专业 skill 自然匹配
2. **强化触发优先级**：在 AGENTS.md 中明确品牌海报任务必须走 brand-poster-creator
3. **增加硬门禁**：在关键步骤（文案确认、创意确认）强制等待用户确认
4. **禁止本地拼图**：在 AGENTS.md 中明确禁止 PIL 拼图作为正式交付

这些修复确保了：
- ✅ 品牌海报需求自动触发完整流程
- ✅ 每个关键步骤都需要用户确认
- ✅ 图片生成必须走正式 API，不得本地拼图
- ✅ 用户体验更好，产出质量更高
